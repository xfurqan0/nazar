# Nazar — project notes and v1 plan

Internal project notes. Kept in English so the repo is readable by everyone.

> **Nazar keeps a watchful eye on your agents.**
> A local, open-source **monitoring** canvas for AI coding agents. Every running Claude Code session is a node on one live canvas; its subagents hang beneath it as a tree; hover shows model, effort, elapsed time, current tool and exact token usage; your quota sits in a strip on top. **It watches. It does not launch, control, or answer permission prompts.**

- Folder: `C:\nazar` · Repo: `github.com/xfurqan0/nazar` — private until the first release · License: MIT
- Siblings: [nazar-tray](https://github.com/xfurqan0/nazar-tray) (quota tray, writes `limits.json`), Dile (dictation). Same repo policy (English everywhere), same rule: **quality over schedule, no deadline; ordered work packages, one finishes before the next starts.**
- Research phase closed 2026-09-07 05:00: market study (6 competitors in depth, 114 cited sources, pain-point clusters, stack and distribution analysis) + data-layer audit on the maintainer's machine (Claude Code 2.1.263, Windows 11). Internal notes hold the full reports.
- Order: **first of the three projects to start coding** (maintainer decision 2026-09-07). Nazar is the CV piece, and its stack is Node/TS, so it needs neither the new machine nor a Tauri/Rust toolchain: it can start on the current PC today. nazar-tray is second, Dile third (its engine experiment needs the new machine). Code starts when the maintainer says go.

## 1. Why it exists, and what the research changed

If you run one agent, a terminal is enough. If an orchestrator spawns parallel subagents while a second CLI works in another window, you tab between terminals asking "which one is doing what, for how long, and what did it cost". The niche is confirmed empty: tools either draw the inside of a *single* session (zoetrope), or give you a canvas where **you** place agents that the tool itself launched (opencove cannot see a `claude` you started in another terminal), or are dead (agent-flow, no commits for two months, tokens estimated as characters/4), or macOS-only (c9watch, the closest real competitor). The only one showing quota does it by pulling your OAuth token, even from another vendor's keychain, and calling an internal API with a spoofed browser user agent.

**The research overturned the first draft's architecture.** Nazar v1 needs **no hooks**. Everything the canvas shows is already on disk or one documented command away; verified on the maintainer's machine:

| Need | Source (v1) | Evidence |
|---|---|---|
| Which sessions are running, where, alive? waiting for what? | `claude agents --json` → `pid`, `cwd`, `kind`, `name`, `status`, **`waitingFor`** (`permission prompt` / `input needed` / `sandbox request` / `dialog open`) | Documented; 380 ms; no TTY needed |
| When to refresh | A poll of `~/.claude/sessions/<pid>.json` with `fs.watch` on top of it (mtime moves on every status transition) | Same pattern as session-kit (629★). **Corrected 2026-09-07 (§3, §8): the watch alone is not enough, because when it delivers is the platform's business and not ours** |
| Subagent tree, model, depth | `~/.claude/projects/<slug>/<session>/subagents/agent-*.meta.json` → `agentType`, `model`, `parentAgentId`, `spawnDepth`, `toolUseId`, `description` | 41 files audited; parent chain closes 100 %; depth 1–3 written into the file |
| Workflow agents | `subagents/workflows/<runId>/` | Visible on disk (the first draft wrongly said invisible) |
| Effort, exact tokens, model id, current tool | Transcript JSONL: `effort` on every assistant line; `message.model`; `message.usage.*`; last `tool_use` block | **Dedupe by `(message.id, requestId)`**: the same message is written once per API block with full usage each time; naive sums inflate 2.08× (measured: 373,980 → 179,402 output tokens) |
| Cost, context window, quota — **in v1 via nazar-tray** | Status-line stdin JSON, captured per session by `nazar-statusline` into `~/.nazar/statusline/<session_id>.json`: `cost.total_cost_usd`, `context_window.*`, `effort.level`, `model`, `session_id`, `rate_limits.{five_hour,seven_day,spend_limit}` | **nazar-tray landed 2026-09-07, so WP3′ turned these on.** The wrapper is nazar-tray’s deliverable and Nazar only consumes it. Optional: an absent capture directory reads as `configured: false`, and nothing is drawn — never `0` |
| Model-scoped weekly quota — **in v1 via nazar-tray** | `~/.nazar/limits.json` from nazar-tray (optional) | Contract frozen in nazar-tray’s `docs/limits-contract.md`; its sample is vendored here as `fixtures/limits.sample.json`. Consumed by WP5, and the only source there is for `seven_day_<model>` or for Codex quota at all |

Hooks become an **optional precision mode** (v1.1): native `type: "http"` hooks (no process spawn) for tool start/stop and permission requests, gated on Claude Code ≥ 2.1.113 (before that an unreachable endpoint silently *denied* tool calls on Windows), `async: true`, installed with a `.bak` and a shown diff, uninstalled exactly. Three of four competing dashboards have no uninstall path at all.

**Corrections to the first draft:** the transcript format is not "documented as internal"; no such statement exists in the docs (the only documented caveat is asynchronous write lag). Teammates **do** fire hooks (`TaskCreated`, `TaskCompleted`, `TeammateIdle`). `claude agents --json` lists **only top-level sessions**, not subagents and not Desktop/VS Code sessions.

## 2. Scope and non-goals

| Nazar **is** | Nazar **is not** |
|---|---|
| Live monitor of every running Claude Code session on this machine, auto-derived, one canvas | A launcher, session manager, kanban, or cost dashboard |
| Subagent tree with depth, model, effort, exact tokens, current tool, "waiting for permission" surfaced prominently | A tool that sends prompts, answers permissions, or manages sessions. **WP4c note: you may move a session's *card*, which changes a picture in your browser and nothing about the session** |
| **Agent history**: finished subagents stay on the canvas faded; past sessions open from disk as a frozen tree with per-agent duration and exact tokens (maintainer decision, 2026-09-07) | A transcript viewer: **metadata only by default**. One exception, added by N-WP15a and opt-in at three independent layers: the **task text** — the last human turn of a session, the launching brief of a subagent — one cleaned line of at most 300 characters, off in every browser until somebody switches it on, absent from the wire unless that browser asked, and not read at all under `nazar --no-task-text`. Still never the model's reply, its thinking, a tool input or a tool result (maintainer decision, 2026-09-09) |
| Local web page served by a small Node process, in a browser tab **or** in the Tauri window and tray that WP8 added around the same page (2026-09-07). The window is the only place a *jump to the terminal* can live | Electron; a cloud service; an account; a bundled Node runtime — Claude Code already needs one |
| Provider-agnostic node model; Codex in v2 | Multi-provider in v1 |

Name: **Nazar** (🧿). Identity: the bead. Provider badges from `@lobehub/icons` (MIT). No Clawd artwork (Anthropic mark; clawd-on-desk assets are all-rights-reserved).

## 4. Known limits (README)

- **Quota, cost and context need a second program installed.** All three reach Nazar through `~/.nazar`, which nazar-tray and its status-line wrapper write and Nazar only reads. With neither installed the strip is hidden and the hover card has no cost or context-window row; nothing is shown as `0`. Installing a status line means writing into `~/.claude`, which is exactly what Nazar does not do — so the install is nazar-tray's own command, run by the user, with its own `--dry-run` diff in front of them.
- **Claude's quota numbers only move while a session refreshes its status line.** Between sessions the strip shows the last reading with its age and a locally computed countdown. Quota does not burn while you are not using it, so that is honest rather than stale.
- **`rate_limits` is not always in the payload.** Pro and Max only, and only after a session's first API response; Claude Code also drops a window once its reset has passed. Each of those is a window with no percentage — drawn grey and labelled `unknown`, never a reassuring `0 %`.
- Desktop-app sessions and the VS Code **extension's** own sessions do not appear in `claude agents --json`; they appear only if their status line runs the wrapper, so in v1 they are unsupported. A `claude` started in VS Code's **integrated terminal** is not one of those — it is an ordinary CLI session, and the jump raises its editor window: measured live on 2026-09-08 (§8), `rung: "a"`, host `Code.exe`. What that measurement did *not* capture is the listing half, and §8 says why.
- Subagents inside a session are not listed by `claude agents`; the tree comes from `meta.json` + transcripts, so a subagent's node appears when its transcript starts, with a small lag.
- "Current tool" of a subagent comes from its transcript's last `tool_use` block; exact start/stop timing needs precision mode (hooks).
- Transcripts are written asynchronously; token totals can lag a few seconds. Nazar shows the age of the last write.
- Codex sessions: v2 (rollout JSONL structure already audited; cumulative `thread_token_usage`, no dedupe needed).
- History reaches back only as far as Claude Code keeps transcripts (`cleanupPeriodDays`, default 30; the maintainer runs 90). Nazar does not extend retention and does not copy transcripts anywhere.

## 5. Node model (v1)

```
Session   { id, provider:'claude', pid, cwd, kind, name?, status, waitingFor?, model?, effort?, startedAt,
            lastWriteAt, contextWindow?:{used?,size?,percent?}, costUsd?, capturedAt?,
            tokens:{in,out,cacheRead,cacheWrite}, currentTool?, agents:[Agent] }
            // WP3': the three capture fields are absent together, on any machine with no
            // status-line wrapper. `contextWindow` became an object rather than a number:
            // "159,283 of 1,000,000" and "16 %" are two different answers and the payload
            // gives both. `effort` prefers the capture's when the capture is newer than
            // the last transcript write, because the transcript's is the effort of a turn
            // that has already happened and the capture's is the one in force now.
Agent     { id, sessionId, parentAgentId?, spawnDepth, agentType, model, description?, startedAt, endedAt?,
            durationMs?, toolCalls?, effort?, tokens:{…}, currentTool?, state: running|done|unknown,
            doneSignal?: 'parent-result'|'session-gone'|'quiet-turn' }   // WP4b: why it is done, never guessed
History   { sessionId, project, cwd?, firstWriteAt, lastWriteAt, durationMs, model?, effort?, tokens:{…},
            treeTokens:{…}, toolCalls?, agentCount, agents:[Agent], roots:[AgentNode], orphans:[id] }
            // frozen; built from meta.json + agent jsonl + session jsonl, metadata only.
            // `cwd` is declared and never filled: a transcript's cwd is on the never-extracted
            // list, so history knows a project by its slug alone (home collapsed to `~`).
HistorySummary { sessionId, project, transcriptBytes, lastWriteAt, agentCount?, hydrated,
                 firstWriteAt?, durationMs?, model?, tokens?, treeTokens? }
            // one listing row. The measured fields exist only once the session has actually
            // been opened (`hydrated`); a directory listing has read nothing and says so.
Quota     { source:'limits.json'|'statusline', updatedAt?, providers:[QuotaProvider] }
QuotaProvider { name, configured, plan?, source?, sourceAt?, binding?, windows:[QuotaWindow] }
QuotaWindow   { key, percent?, resetsAt?, windowMinutes?, state, error?, model?, detailed? }
            // WP5. `providers` is a *list*, not the object the first draft declared: the
            // strip draws them in order and a file's key order is the only order there is.
            // `percent` is optional by contract — absent is drawn grey and called `unknown`,
            // never `0 %`. Everything derived (binding, countdown, age, severity) is computed
            // where it is drawn, from these numbers plus the clock, and never stored.
            // Absent entirely when neither source exists: that is how the strip stays hidden.
```

## 7. Open decisions
- **The canvas's language and the shell's are resolved separately** (N-WP13). The canvas keeps the user's choice in `localStorage`; the tray menu is built before any page exists and reads the operating system's UI language instead. They agree on a machine whose user has not overridden the canvas, and disagree on one who has. Carrying the choice across would mean an IPC call and a settings file the desktop shell does not have; the same argument leaves the boot screen (`apps/desktop/shell/`) in English, since it is what is shown when there is no Node to run the canvas with at all. **The command line stays English regardless**: `bin/nazar.mjs` and `nazar doctor` are a maintainer's surface, and a translated diagnostic is one a maintainer cannot search for.
- ~~Layout library for the per-session tree: dagre vs elk~~ → **decided 2026-09-07 in WP4: none.** The layered tree is ~50 lines in `packages/ui/src/layout.ts` (leaves take the next free slot, a parent centres over its children, roots wrap onto a new band past a width cap), so not even `d3-hierarchy` was needed. Runtime dependencies stay at zero.
- ~~Whether the status-line wrapper ships inside Nazar or as a tiny shared package~~ → **decided 2026-09-07: neither.** One owner (nazar-tray), one written contract, two consumers. Nazar is a consumer only. **Held up in WP3′ (2026-09-08):** consuming it cost one 400-line reader and one vendored fixture, the contract needed no change in either repository, and the "shared package" that was not built would have put Node in front of nazar-tray's one-binary claim for no gain on this side.
- ~~Port: fixed default with `--port` override, or `listen(0)` + a discovery file~~ → **decided 2026-09-07 in WP8: the fixed default, `4676`, with a `--port` override and no discovery file anywhere.** `packages/server/src/cli.ts` holds `DEFAULT_PORT = 4676`, `--port 0` is rejected there along with everything else outside 1–65535, and `packages/server/test/cli.test.ts` pins the refusal. **Answered by WP8:** the desktop shell needs a port nobody has, and it does not need a discovery file to find it, because it *is* the parent — it binds an ephemeral port, releases it, passes it with `--port`, and reads the URL back off the child's stdout. `--port 0` was deliberately **not** taught to the CLI: `packages/server/test/cli.test.ts` pins that 0 is rejected, and a published contract is not worth bending for one caller. The race between releasing the probe port and the child binding it is handled by retrying, and detected rather than assumed, because the child announces the URL it actually bound.
- **Code signing for the desktop installer.** It is unsigned today, so SmartScreen warns on first run until the download builds reputation, and every warning costs installs. Not worth a certificate for a pre-alpha with an unknown number of users; the trigger to revisit is the download count, and it is kept out of the v1 gate on purpose (`docs/RELEASE.md`, step 10).
- ~~Multi-canvas tabs and drag-to-move: v2~~ → **moved into v1 on 2026-09-07 (WP4c), by the maintainer, after running the release candidate on his own machine.** The estimate behind "not needed until sessions exceed one screen" was wrong in both directions: one real session with ~60 subagents already exceeds one screen on its own, and the grid put every session in a single column long before that. The deciding sentence was his: *"the reason this is a canvas is to put sessions wherever I want."* The whole feature is browser-side (`localStorage`), so it costs nothing on the server and does not touch the "writes nothing" gate.
- ~~**Where browser-local state lives in the desktop shell.**~~ → **decided 2026-09-08 in N-WP9: persist the chosen port.** The first of the three ways out, and the only one that costs nothing else. `apps/desktop/src/config.rs` grew a `port` key, `apps/desktop/src/server.rs::plan_port` reuses it when it is free, *adopts* the server already on it when that server is a healthy Nazar of the same version, and asks the operating system for another only when neither holds — so the arrangement is lost once, when the number genuinely has to change, rather than on every launch. A custom protocol would have moved the canvas off `http://127.0.0.1`, which is the origin browser mode uses and the one the CSP and the `Host` allow-list are written for; moving the workspace off `localStorage` would have ended "Nazar writes nothing", which is the promise the whole design rests on. **A fixed default was rejected for a reason worth keeping**: 4676 is what `npx @xfurqan0/nazar` binds, so a shell hard-coded to it would fail whenever the browser copy was running, and a shell that bound it first would make the browser copy fail instead. The original note follows. `apps/desktop/src/server.rs:208` called `free_port()` on every launch — `server.rs:176-184` binds `127.0.0.1:0`, reads the port back off the listener and drops it — and `apps/desktop/src/config.rs:40-55` persists only `schema_version`, `autostart` and the keys this build did not recognise. The port is never stored. `localStorage` is keyed by origin *including the port*, so in the desktop app the arrangement (`nazar.layout.v1`), the tabs (`nazar.tabs.v1`), the sticky notes (`nazar.notes.v1`), the card names (`nazar.names.v1`), the colour overrides (`nazar.colours.v1`) and whether the usage panel is open (`nazar.usage.v1`) land on a different origin every launch, and the app forgets all six on every restart — while a browser tab on a stable `--port` does not. Three ways out: persist the chosen port in `desktop.json` and reuse it; serve the canvas from a stable custom protocol; or move the workspace off `localStorage`, which would end the "Nazar writes nothing" promise. Not decided.

They agreed, and they agreed only for as long as nobody edited one of them — a card framed amber while the strip said nobody was waiting would be the canvas contradicting itself in two places at once.   **The second cluster is the smallest honest version of "show me the result".** *Finished while you were away* lists a session that had work in flight on the previous frame and has none on this one — and *in flight* is a wider question than the card's own activity word, on purpose: a session whose last human turn was answered an hour ago reads `idle` on its card while six subagents run underneath it, and it has not finished until its tree has. It stays for ten minutes and then clears itself; it leaves early if the session picks work up again, or if the machine stops listing it at all, because a row whose card is gone would be a button that goes nowhere. An `unknown` agent does not count as a running one, for the reason nothing else here guesses either.

  **What this package refuses to do is most of what it could have done.** No *stuck* verdict: a session that has written nothing for an hour is a session somebody left open, and no amount of silence turns that into a fact — README's Known limits carries the sentence, because the absence is a decision and not an omission. No toast and no sound: desktop notification is nazar-tray's job and Nazar still neither writes nor makes noise. No list view, no third pane, and not one pixel of the card changed.

  **`jumpSupported` rode along because N-WP19a made it a bug.** `ShellInfo` has carried the field since WP8 and nothing on the page read it. That cost nothing while Windows was the only bundle. The day macOS and Linux bundles shipped it became visible: `apps/desktop/src/jump.rs` is `cfg!(windows)`, its own doc comment says *the canvas asks `supported()` before offering the entry*, and the canvas never asked — so a mac user got a **Jump to terminal** item in every card menu whose one possible answer was *not available on this platform yet*, and a double-click that did nothing anybody could see. Both menus now ask a `canJump()` at the moment they draw, the gesture itself returns early, and the *double-click a card* sentence in About goes with them. It is silent rather than apologetic: a hint would fire on every double-click of a card to repeat a fact about the platform that does not change, and the menu entry is not there to be found in the first place.

  **The tests drive it.** N-WP20's DOM double grew four things this needed — `getBoundingClientRect`, `style`, `offsetWidth`/`offsetHeight` and `insertBefore`/`firstElementChild`/`nextElementSibling` — so a popover that anchors itself and a list that *moves* the rows that are out of place can both be run rather than grepped. That matters here because the two bugs this shape of component has are invisible to a source scan: a list whose order is the order rows were created rather than the order they were sorted into, and a row whose handler fires with the wrong session. So a newer wait that outlives an older one is asserted to move up the list; a click is asserted to reach the canvas with the right id; and the jump is asserted to fire in a shell, never in a browser, and never on a shell that says it cannot. 942 tests against 900.
